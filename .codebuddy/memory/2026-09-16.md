## webman 编译 EXE 的「改源码不生效」陷阱

- `webman/typephp-dms-webman.exe`（88MB）是把 webman 源码 + krowinski vendor 一起打包的编译产物。
- 现象：binlog 解析子进程 `krowinski_dump.php` 退出码 255，报错 `Call to undefined function MySQLReplication\Socket\socket_shutdown()`（krowinski `Socket::__destruct` 依赖 ext-sockets）。
- 根因不是代码没改：源码里已有 `function_exists('socket_create')` 围栏（会给出清晰的「缺少 ext-sockets」提示而非 255）。用户看到的裸 255 说明**跑的是旧 EXE**——旧构建打包了加围栏之前的代码。改 `.php` 源码不会自动生效，必须**重新构建 EXE**。
- 修复：①重新构建 EXE；②在 EXE 同目录放 `php.ini` 启用 `extension=sockets` 并设对 `extension_dir`（别用默认 `C:\php\ext`）；③或绕过 EXE 直接用带 sockets 的 php 跑 `php windows.php` / `php start.php start`（如 PhpWebStudy php 8.4）。
- 已把 WsHandler 与 krowinski_dump.php 的围栏从仅查 `socket_create` 改为同时查 `socket_shutdown`（实际崩掉的符号）。
- 经验：凡是改动 `webman/` 下会被 EXE 打包运行的文件，都要提醒重新构建 EXE 才能生效。

## 时间窗口追溯「转圈不停」：endTs 落在未来

- 现象：历史追溯（时间窗口 13:42–15:42，当前 ~15:00）一直转圈不停，心跳帧持续推送。
- 根因：`TracePage` 表单允许结束时间选到未来（validateRange 只查 end>start）；worker 退出条件是「行事件越过 endTs」或「心跳兜底 time()>endTs+2」，endTs 在未来时两者都要等到那一刻才成立 → worker 一直 tail。
- 修复：`WsHandler::handleBinlogDump` 里把 endTs 收敛 `min($endTs, time())`——历史追平后心跳兜底 ~2s 内退出并发 binlog-end，前端 isEnded 正常出结果。
- 前端 `passedEnd`（事件 ts > endMs）对未来 endTs 永不成立，不能依赖它收尾；必须靠 binlog-end。
