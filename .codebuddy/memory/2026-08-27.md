## webman /dump 无响应修复

**问题**：webman 项目的 `POST /dump` 端点无响应，前端发送 binlog-dump 请求后卡住。

**根因**：webman 的 `WsHandler::onDump()` 返回 `Response` 对象，webman HTTP 协议编码器会添加 `Content-Length: 0` 并关闭响应，后续通过 `Chunk` 推送的 SSE 帧被丢弃。

**修复**：参考 `agent-workerman` 的实现，绕过 webman HTTP 编码器：
1. `onDump()` 设置 `$connection->protocol = null`，直接发送裸 HTTP 响应头（`Transfer-Encoding: chunked`）
2. `sendFrame()` 改用 `$conn->send("data: ...")` 裸 socket 发送，不再用 `Chunk`
3. `teardownDumpWorker()` 改用 `$conn->close()` 结束流，不再发空 Chunk
4. 移除不再使用的 `Chunk` import

**文件**：`webman/app/DmsAgent/WsHandler.php`

## 生成 BinlogTrace 功能讲解 PPT

用 huashu-slides (Path A 编辑型 HTML) + svg-studio 技能生成了 12 页漫画风（Manga Educational）PPT：
- 文件：`outputs/BinlogTrace-功能使用讲解.pptx`（可编辑），源 HTML：`outputs/slides/slides.html`，插画 SVG：`outputs/ppt-assets/`，截图用 `outputs/01-08-*.png`。
- 插画用 svg-studio 的 `render.py` 渲染 PNG（Chrome 失败回退 resvg，中文字体 OK）。
- **关键坑**：`html2pptx.js` 的 CLI 是位置参数 `node html2pptx.js <html> <output.pptx>`，不能用 `--output`。其 `html2pptx_official.js` 对 `file://` 绝对路径解析有 Windows bug（`replace('file://','')` 把 `file://D:/` 变成 `/D:/` 再拼成 `C:\D:\`），已改为 `replace(/^file:\/\/\/?/, '')` 修复（两处：背景图 240 行、图片元素 334 行）。图片 src 用 `file://D:/...` 双斜杠形式可正确解析为绝对盘符路径。
- 该脚本依赖：`pptxgenjs`（装到 export 目录）、`playwright` + `chromium`（`npx playwright install chromium`）。

## bny 打包 webman 成功

- 配置文件：`webman/bny.json`（name=typephp-dms-webman, main=./start.php, ignore runtime/.git/tests/）
- 命令：`bny.exe compile . -o typephp-dms-webman`
- 产物：`D:\git\php\typephp_dms\webman\typephp-dms-webman.exe`（约 89 MB，仅含 webman + 自身 vendor）
- 运行测试：启动后监听 8080，`GET /ping` 返回 `{"ok":true,"message":"BinlogTrace Agent (Webman HTTP mode)"}` ✅
- **坑**：第一次打包时 bny 扫描根跑到工作区父目录，把 `frontend/node_modules`（约 574MB）也打进去了。修复：在 `webman/bny.json` 的 `ignore` 里显式排除 `frontend/ agent/ parser/ docs/ outputs/ dist/` 等。
- **坑2**：bny 用 Enigma Virtual Box 封包，编译前不能手动删掉旧的 exe（会报 `does not exist`），需先 `bny clean` 再 `bny compile`。
- 产物落在 webman 目录内（不是工作区根）。编译耗时约 3 分钟。
