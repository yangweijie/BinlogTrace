# 2026-08-26

## 继续：把 agent 编译产物接上 pdo_mysql（TypePHP 原生 Windows）
- 诊断信息重构：`AgentHandler::diagnosticInfo()` 改为返回**分字段数组**（pdo/pdo_mysql/mysqli/mysqlnd/php_ini/extension_dir/php_version/zts/debug/arch/sapi/module/extensions），connect 失败响应拆出独立 `diagnostic` JSON 字段，message 不再堆文本。验证 php -r 下结构正常。
- 关键根因澄清：`PHP_HOME` 仅编译期用于 tpc 找 `php8ts.lib`；运行时 Windows 按 DLL 搜索顺序加载 `php8ts.dll`，所以产物实际加载的是 `C:\php\php8ts.dll`（PATH 中排在 PHP_HOME 前），与 PHP_HOME 无关。诊断 `php_ini:(none)`、`extension_dir:C:\php\ext` 印证。
- `mysqlnd` 是底层传输，不能顶替 `pdo_mysql` 驱动；PDO 驱动表缺 "mysql" 才报 could not find driver。需静态编进 `--with-pdo-mysql=static`。
- agent 代码实际只用 PDO+pdo_mysql（无 curl/mysqli）。
- 新增 `agent/build_php_pdo_mysql.bat`：在 php-sdk 开发者命令行运行，抓取现有 C:\php 的 configure 命令、追加 `--with-pdo-mysql=static`，重编并把 php8ts.lib/php8embed.lib/php8ts.dll 导出到 staging。
- `agent/project.yml` 的 `ext-deps` 从 `[pdo_mysql,mysqli,curl]` 精简为 `[pdo_mysql]`（匹配实际用法，避免对未构建扩展的 ZEND_MOD_REQUIRED）。
- 部署要点：让带 pdo_mysql 的 php8ts.dll 在运行期被优先加载（放 binlog-agent.exe 同目录，或 PATH 中 C:\php 之前）。
