## 前端代码审核 (frontend/)
对 TypePHP DMS 前端做了全面代码审核（bug + 体验）。核心发现：

**高严重**
- `src/lib/ws.ts:18` `BASE` 硬编码 `http://127.0.0.1:8080`，真实连接忽略用户填的 host/port。
- `ws.ts` `streamPost`/`close()` 无 `AbortController`，SSE 流无法被真正中止；`cancel()`、组件卸载后流泄漏。
- `useTraceRun.ts` 订阅回调每事件 O(n) 遍历全量 `changes/events` 计算进度（高频 binlog 流 O(n²)，数万条卡死）。
- TracePage/ResultPage 卸载未调用 `cancel()/clearSession()`，SSE/worker 泄漏。

**中**
- `useTraceRun` `flushCache` 每 60 条整体克隆 `session.changes`（O(n²)）。
- ResultPage:217 在 demo 模式（无真 WS）仍 `status=connected`。
- `change-cache.ts` 上千条含 base64 BLOB 的 Change 易超 5MB localStorage 配额，刷新丢数据。
- `ChangeDetailModal`/`MultiSelect` 无 Esc 关闭/焦点陷阱，可访问性差。
- `SqlViewer` `dangerouslySetInnerHTML` 全量正则高亮，大 SQL 重渲染卡顿。

**低**
- `workers/demo-parse.ts:68` `const columns = DEFAULT_COLUMNS;` 死代码（for 外未用）。
- `check-meta.ts` `binlog_format` 大小写敏感比较。
- ConnectPage `blocking` 把 info 级降级误判为阻断，文案误导。
- `useRefLoad` 命名误导（实为 useState）。

未改动代码，仅出具审核报告。

## 继续修复 #4 #5
- #4（cancel 可靠清理 + 防重入）：
  - `TracePage.tsx:190` 主按钮 `disabled` 增加 `trace.collecting`，防止采集期间重入触发第二个 `run()`（竞态）。
  - `useTraceRun.cancel()` 调 `session.close()` 后额外 `clearChanges()` 清理 localStorage 脏缓存，避免 ResultPage 误读取消后的残留结果。
  - 组件卸载 cleanup 已在上一轮加 `session.close()` 防 SSE 泄漏。
- #5（O(n²) 消除）：当前 `useTraceRun` 已无初版报告所指的 `pullLoop/flushCache` 每60条整体克隆（该版本重构过）。改为落实等价优化：
  - `structuredToChanges` 支持可选窗口 `[startMs,endMs]`，**单次遍历**内完成窗口过滤+映射（原 `finalizeStructured` 先 `filter` 再 `map` 两遍 O(n)）。
  - demo 路径 `finalize` 用单遍 `for`+早 `continue` 替代 `filter().map()`，避免 `eventTypeName` 重复调用。
  - 验证通过 tsc 与 build。

结论：#4 竞态/泄漏已闭合；#5 原 O(n²) 克隆在当前代码已不存在，已做 finalize 阶段 2n→n 遍历合并优化。
