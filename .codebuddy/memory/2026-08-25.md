# 2026-08-25 — binlog_agent 编译链路诊断与修复

## 核心结论
- PDO MySQL 在 Windows tpc bin 模式完全不可用（根因：产物内置 ini 写死 C:\php、无 pdo_mysql 构建配置、LibPhpInstaller 仅 Linux embed）。改用 C++ libmysqlclient 直连绕开 PDO。
- tpc_v1113 是网友给的预构建 tpc.exe + phpx 发布包（版本未知），与 git 上 aot-compiler 源码版本可能不完全一致，但**用预构建 tpc.exe 配 tpc_v1113 的 phpx 实际可编译**（版本匹配）。源码 `php bin/tpc.php` 路线因缺 phpx.dll/typephp_runtime.h 走不通，但预构建 tpc.exe 路线可用。

## 关键修复记录
1. **预构建 tpc.exe 运行需 junction**：它硬编码调 `D:\workspace\compiler\src\compiler.php`（逻辑路径）。在 `D:\workspace\compiler` 建 junction → `D:\git\php\aot-compiler` 即可让它读外部源码。且给 `aot-compiler/src/compiler.php` 顶部加了幂等 autoload require（`if (!class_exists('PhpParser\\ParserFactory', false)) require __DIR__.'/../vendor/autoload.php';`），解决预构建 tpc.exe 内嵌代码缺 composer autoload（报 ParserFactory 未定义）的问题。
   - ⚠️ 用预构建 tpc.exe 前必须：① 建 junction D:\workspace\compiler → aot-compiler；② vcvarsall.bat x64 初始化 VS 环境（否则 cl 找不到 cstring 等标准库头）。
2. **link-libs 必须带 .lib 后缀**：`project.yml` 的 `link-libs: [libmysql]` 会被 MSVC 链接器当成 `libmysql.obj`（LNK1181）。改为 `link-libs: [libmysql.lib]` 即可（和 user32.lib 等一致）。`link-paths` 指向 connector 的 lib 目录。
3. **phpx API 要点**（mysqlbox.cc）：php 命名空间类型用 `Variant`（无 Value 别名）、`Str` 取字符串用 `toCString()`（非 c_str()，那是 std::string 的）、`Array::set` 的 key 用 `Str` 而非 `std::string`。Box 子类 `class MySQLBox : public Box`，`return {new MySQLBox(c)}` 隐式转 Variant。C++ 函数 `php_mysqlbox_*` 在 PHP 侧名 = 去 `php_` 前缀，需 `mysqlbox.stub.php` 空函数体声明（放 sources，返回类型必填，如 `:mixed/:array/:string/:void`，参数可用 `mixed`）。

## binlog dump 协议层攻关（续）
- **COM_BINLOG_DUMP 必须用底层 net_write_command 发 COM_BINLOG_DUMP(0x12)**，不能用 mysql_real_query（会被当 COM_QUERY 当 SQL 解析 → 1064 语法错误）。包体 = pos(4,LE)+flags(2)+server_id(4)+filename。
- **Connector/C 6.1.11 的 libmysql.lib 不导出 my_net_read**（LNK2019），改用自写 `sock_read_full`/`read_one_packet` 基于 `recv(net->fd)` 直接读 MySQL 包（4字节头+负载），并 `setsockopt(SO_RCVTIMEO=2000ms)` 实现超时轮询 stopFlag。
- **pkt_nr 序列号是关键坑（最终用探测法解决）**：server 报 1156 "Got packets out of order"。
  - libmysql 的 mysql_real_query 发 SET 后 net->pkt_nr=2，但 DUMP 用 2 发仍被 server 拒（说明 server 期望的 DUMP pkt_nr 不是 2，且无法静态确定——可能与 caching_sha2 auth 多轮握手、libmysql/Connector-C 6.1.11 旧版行为有关）。
  - **最终方案（探测法）**：COM_BINLOG_DUMP 发送改为探测循环——从 startPktNr 起，逐个 pkt_nr 尝试发包+读首个响应，遇到 1156(ERR) 则 pkt_nr+1 重发（最多 12 次），命中 OK/事件包即停止。这样无需猜测正确序号，自动对齐 server 期望。SET 仍用 mysql_real_query 维护前半段序列；DUMP 及后续事件流用自写 read_one_packet(recv) 读。
  - 用固定 startPktNr 计算每次探测序号，避免 my_net_write_command 内部 pkt_nr++ 污染。
- SET 语句长度之前硬编码错（36/29 而非 strlen 的 35/30），导致越界字节污染 net 状态，已改 strlen()。
- mysql_options(MYSQL_OPT_READ_TIMEOUT) 在 connect 后设置无效，改直接 setsockopt。
- ERR 包已能解析：0xFF + code(2,LE) + '#' + sql_state(5) + message。
