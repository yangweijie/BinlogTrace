## 三、AI・智能应用 落地应用详情

### ① 所用 AI 工具 / 自研功能的核心能力说明

本应用是一套面向数据库运维与数据安全的"智能数据变更追踪与一键回滚"工具，核心解决三类长期痛点：

1. **误操作难追溯**：生产库发生误删 / 误改后，传统方式依赖人工翻 MySQL 二进制日志（binlog），耗时长、门槛高、易遗漏。本工具通过智能解析引擎，自动将 binlog 转化为结构化、可读的变更记录（精确到"哪张表、哪一行、改前 / 改后的值、操作时间、事务 ID"），分钟级定位"谁在何时改了什么"。
2. **回滚 SQL 手写易错**：数据修复需人工逆向编写 UPDATE / DELETE / INSERT，字段多、记录多时极易写错，造成二次事故。本工具基于解析出的前后镜像，**自动生成可执行的回滚 SQL**，支持预览、复制、批量生成，把"专家手艺"变成"标准化输出"。
3. **历史时间点难定位**：要找回"某天某时的数据状态"，传统方式需全量扫描日志。本工具支持按时间窗口快速检索对应 binlog 区间，秒级缩小排查范围（历史点定位）。

> 智能属性说明：本工具采用"自动解析 + 自动代码生成"的智能化范式，将原本高度依赖资深 DBA 经验的 binlog 解读与回滚 SQL 编写工作，转为系统化、可复用的自动能力，显著降低岗位门槛、提升准确率与时效。

### ② 落地使用流程与日常应用场景

**日常使用流程（5 步）：**

1. 运维 / 开发在连接页填入数据库地址，或一键进入演示模式零风险验证功能；
2. 设置追踪条件（目标库表、变更类型、时间范围）；
3. 系统实时解析 binlog 流，界面以列表 + 详情展示每一笔变更；
4. 发现误操作后，勾选目标变更，一键生成回滚 SQL；
5. 复制 SQL 到数据库执行完成修复，全程可审计留痕。

**典型应用场景：**

- 生产数据误删 / 误改后的紧急修复（DBA 应急核心场景）；
- 上线变更前的变更审计与回溯；
- 业务方质疑"数据被改过"时的取证核对；
- 新人培训演示（演示模式，零生产风险）。

> 佐证材料建议：可使用本工具"演示模式"录制一段"连接 → 追踪 → 生成回滚 SQL"的操作录屏，作为最直观的落地佐证（全流程可零风险跑通）。
