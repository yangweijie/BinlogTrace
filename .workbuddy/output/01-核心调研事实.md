# 核心调研事实（团队总监汇总，2026-08-22）

## 1. 硬约束：浏览器无法直连 MySQL（TCP 层不可行）

- 浏览器沙箱禁止 WASM/JS 直接建立 OS 级 TCP Socket 到 MySQL 3306
- 证据：webpack `node-libs-browser` 将 `net`/`tls` 映射为 null（无 TCP 能力）
- Emscripten 的 POSIX socket 模拟是把 `socket()`/`connect()` 代理为 WebSocket，**仍需额外代理端**
- WebTransport（2026 baseline）也不可行：MySQL 协议基于 TCP，非 QUIC；且 Safari 26.4+ 才支持
- **结论：WASM 解决的是"解析/计算"问题，不解决"网络连接"问题**

## 3. 回滚 SQL 生成标杆：binlog2sql flashback 算法

- DELETE → INSERT（恢复被删行）
- UPDATE → 前后值互换（SET 原值 WHERE 新值）
- INSERT → DELETE（按主键条件）
- 按事务逆序输出（最后提交的先回滚）
- 引用：https://github.com/danfengcao/binlog2sql

## 4. 连接桥接方案

| 方案 | 用户安装 | 凭证安全 | 可行性 |
|------|---------|---------|--------|
| WebSocket TCP 代理（自建，如 websocat/自写~100行） | 需下载单文件 agent | 明文经代理 | 最接近"零安装" |
| Cloudflare Workers + Hyperdrive + mysql2(disableEval) | 需 CF 账号 | 凭证在 Worker 侧 | 免本地服务端 |
| 原生 TCP | 无 | - | **不可行** |

## 5. 对标产品：阿里云 DMS 数据追踪（功能规格）

- 前提：MySQL 5.6+、开启 Binlog
- 追踪 DML（INSERT/UPDATE/DELETE），不支持 DDL
- 时间范围：自由操作 30 分钟；稳定变更/安全协同 48 小时（受 Binlog 保留时长限制）
- 输出：回滚脚本（可下载）+ 按库/表/列筛选
- 流程：建工单 → 审批 → 日志下载解析 → 勾选变更记录 → 导出回滚脚本 → 数据变更工单执行
