## 浏览器内 MySQL 数据追踪工具 — 技术调研（MVP 专家团）

**任务**：调研"浏览器内 MySQL 数据追踪工具"（对标阿里云 DMS 数据追踪）的开源方案与最小实现路径。

**关键结论**：
1. 纯浏览器零服务端直连 MySQL 在 TCP 层不可行（浏览器沙箱硬约束）；WASM 解决解析不解决连接
2. 市场空白：不存在浏览器内 binlog 追踪+回滚生成的完整开源产品
3. 解析核心复用 @vlasky/zongji（MIT，纯 JS 可剥离）；回滚算法复用 binlog2sql flashback
4. 最小桥接面：CF Workers+Hyperdrive（首选，无本地服务端）或单文件 WS TCP 代理（内网兜底）
5. 四层架构：连接层→解析层→回滚层→UI 层；MVP 约 2-3 周

**产出**：`.workbuddy/output/report.md`（完整报告）、01-核心调研事实.md、02-决策日志.md；`docs/decisions/OPEN-DECISIONS.md`（3 项 OPEN：解析核心选型/桥接方案/WHERE 精度）

**OPEN 待用户确认**：解析核心 zongji vs Rust/WASM 优先级；桥接方案选 CF 还是 WS 代理；binlog_row_image 配置

## 追加：用户决策 + Spec v1.0（Phase 1.5）

**用户 3 项决策（2026-08-22 10:02）**：
1. **解析核心**：用本仓库 aot-compiler（即 TypePHP, swoole/typephp）——支持 wasm32-wasip2 编译（`wasm: browser` 库模式 + `#[WasmExport]` + Jco 集成），也支持原生独立二进制。一套 PHP 代码双目标：WASM 给浏览器解析核心、原生二进制给 WS 代理端
2. **桥接**：内网单文件 WS 代理（TypePHP 原生二进制，免 PHP 环境）；CF Workers 降为后续可选
3. **回滚 WHERE**：用全列（binlog_row_image=FULL）

**关键 ABI 约束**：TypePHP wasm browser 模式导出函数仅支持 bool/int/float/string/void（int→WIT s64→JS bigint），数组/对象/引用/生成器为编译错误 → 接口设计为"binlog 字节流(string)进，JSON 事件流(string)出"
